# Mission: Jev를 시스템 안에 설계해 넣을 수 있는 엔지니어 되기

## Why
LLM 에이전트 하네스, 분류·스코어링 파이프라인, 실시간 결정 루프에 Jev(TypeSafe AI의 System One Model)를 어디에 어떻게 넣을지 코드 없이도 설계할 수 있어야 한다. 실제 구현은 팀이나 에이전트에 맡기더라도, 질문 세트·state·임계값·아키텍처를 내가 정하고 그 근거를 설명할 수 있는 상태가 목표다. 원리(비자기회귀 병렬 샘플러, RLCD, 캘리브레이션)를 화이트보드로 설명할 수 있어야 설계 결정에 확신이 생긴다.

## Success looks like
- 주어진 업무(예: 지원 티켓 라우팅, 툴콜 가드레일, RAG 리랭킹)를 Noul/Choice/Score 질문 세트로 분해하고, state에 무엇을 넣고 무엇을 빼야 하는지 설계할 수 있다.
- confidence 기준 auto/confirm/human/block 분기 정책을 근거 있게 정하고, "임계값은 도메인 간 이전되지 않는다"는 점을 반영해 검증 계획까지 말할 수 있다.
- LLM 에이전트 하네스 안에서 Jev가 들어갈 위치(라우터·게이트·판정자·압축기)를 아키텍처 다이어그램으로 그려 설명할 수 있다.
- System One vs System Two, 비자기회귀 병렬 샘플러, RLCD, 캘리브레이션의 의미와 한계를 화이트보드 5분 설명으로 전달할 수 있다.
- "이 유즈케이스에는 Jev가 맞지 않는다"를 안티패턴 목록(자유 텍스트, 근거 필요, 32K 초과, 기권 옵션 없음, 확률을 정렬 키로 쓰기 등)에 근거해 판단할 수 있다.

## Constraints
- 주 5시간 이상 투입, 레슨당 30분 안팎, 매일 1개 레슨 가능.
- 학습 언어는 한국어.
- **코드는 쓰지 않는다.** API 요청/응답 형태(JSON 모양)와 다이어그램까지만. 실습은 질문 설계·임계값 표·아키텍처 그림으로 한다.
- 자료 접근 제약: 공식 문서 원문은 이 환경에서 직접 열 수 없어 GitHub 미러(thiagoadril/typesafe-docs)와 커뮤니티 코드에 의존한다. 확인 못한 수치는 반드시 표기한다.

## Out of scope
- TypeSafe와의 가격 협상·계약 조건·라이선스.
- 실제 SDK 코딩, 배포, CI 연동.
- open-jev/DeBERTa 파인튜닝 같은 재현 실습 (원리 이해 수준까지만, 직접 학습은 하지 않음).
- 비기술 의사결정자용 피치·ROI 화법 (→ `learn/jev-sales/` 워크스페이스).
