Jev 10분 설명 대본

하이레벨에서 시작해 한 칸씩 내려가는 비계(scaffolding)식 구성이다. 어느 칸에서 멈춰도 그때까지의 이야기가 완결되도록, 칸마다 "여기서 끊어도 되는 한 문장"을 두었다.

새 버전이 있다

IT를 모르는 친구에게 객관식 시험 비유로 설명하는 파인만식 대본으로 다시 썼다. 이 페이지는 개발자·의사결정자용 비계식 원본으로 남겨 둔다.

가정한 청중

개발자와 의사결정자가 섞인 자리. LLM(ChatGPT, Claude)은 써 봤지만 Jev는 처음 듣는 사람들. 청중이 전부 비개발자라면 4번 칸을 1분으로 줄이고 5번 칸을 늘린다(맨 아래 "시간이 모자랄 때").

전체 사다리

위로 갈수록 넓고, 아래로 갈수록 깊다. 처음 1분은 "무엇이 문제인가"만, 마지막 1분은 "그래서 무엇이 바뀌나"만 말한다.

0:00① 문제 — LLM에게 if문을 시키고 있다
1:00② 정체 — 말 대신 결정을 돌려주는 모델
2:30③ 원리 — 왜 빠르고 싼가, 대신 무엇을 잃나
4:30④ 설계 — 코드가 주인, Jev는 판정 한 칸
6:30⑤ 자리 — 어디에 맞고 어디에 안 맞나
8:00⑥ 정직한 숫자 — 광고와 실측
9:15⑦ 맺음 — 결정의 주인이 바뀐다

아래 타이머로 리허설하라. "시작"을 누르면 현재 칸이 강조되고 화면이 따라 내려간다. 칸 제목을 누르면 그 시점으로 건너뛴다.

0:00–1:00LEVEL 0① 문제: LLM에게 if문을 시키고 있다
여기서 끊어도 되는 한 문장우리는 지금 글쓰기 기계에게 "예/아니오"를 시키고, 그 글을 다시 파싱해서 쓰고 있습니다.

요즘 서비스 안에서 LLM이 하는 일을 떠올려 보시면, 생각보다 많은 게 "글쓰기"가 아니라 "판정"입니다. 이 문의는 결제팀인가 기술팀인가, 이 댓글은 스팸인가, 이 툴 호출은 실행해도 되나.

그런데 LLM은 사람이 읽을 문장을 만들도록 훈련된 모델입니다. 그래서 우리는 "JSON으로 답해"라고 부탁하고, 수백 개 토큰을 기다리고, 돌아온 글을 다시 파싱해서 if문에 넣습니다.

TypeSafe라는 회사는 이걸 "불일치"라고 불렀습니다. 판정이 필요한 자리에 글쓰기 기계를 쓰고 있다는 거죠. 오늘 소개할 Jev는 그 자리를 위해 처음부터 다르게 만든 모델입니다.

화면지원 문의 한 줄 → LLM → 긴 JSON 텍스트 → 파서 → if문. 화살표 네 개.
근거공식 Introduction 첫 단락 "mismatch".
"그럼 '판정 전용 모델'은 뭘 받고 뭘 돌려줄까요?"
1:00–2:30LEVEL 1② 정체: 말 대신 결정을 돌려주는 모델
여기서 끊어도 되는 한 문장Jev는 글 대신, 내가 미리 정한 선택지 중 하나와 그 확률을 돌려주는 모델입니다.

Jev는 TypeSafe가 9월 15일에 얼리 액세스로 공개한 모델입니다. ChatGPT의 기반 기술인 RLHF를 공동 개발한 전 OpenAI 연구원 디오고 알메이다가 세운 회사이고, DCVC가 이끈 4천만 달러 시드 투자를 받았습니다.

계약은 단순합니다. 판단 재료인 state와, 답의 형식이 정해진 질문을 보냅니다. 그러면 글이 아니라 타입이 정해진 답과 확률이 돌아옵니다.

질문은 딱 세 종류입니다. 여러 개 중 하나를 고르는 Choice, 단계 위의 위치를 매기는 Score, 참일 확률을 묻는 Noul. 예를 들어 "결제·기술·영업 중 어느 팀?"에 billing 0.84, "얼마나 화났나?"에 1.0, "환불을 요청하나?"에 0.96이 돌아옵니다. 코드는 이 숫자로 바로 분기합니다.

이름은 카너먼의 "생각에 관한 생각"에서 왔습니다. 빠른 직관의 System 1, 느린 숙고의 System 2. Jev는 System 1, "전문가가 1초 만에 내리는 판단"을 겨냥합니다.

state : "Stripe 연동이 3일째 실패해요. 매출이 날아가요. 급해요." 질문 : 팀은? (billing / technical / sales) ← Choice 화난 정도? (0 침착 · 1 불만 · 2 분노) ← Score 급한가? ← Noul 답 : billing 0.84 · 1.0 · 0.999
화면위 판서 그대로. 답 칸에 숫자가 채워지는 순간을 천천히.
근거공식 Quick start 예제, System One 개념 페이지. 레슨 0001.
"그런데 어떻게 이게 LLM보다 훨씬 빠르고 쌀 수 있을까요?"
2:30–4:30LEVEL 2③ 원리: 왜 빠르고 싼가, 대신 무엇을 잃나
여기서 끊어도 되는 한 문장LLM은 답을 한 글자씩 "만들고", Jev는 내가 준 선택지에 한 번에 "점수를 매깁니다". 그래서 빠르지만, 더 오래 생각할 수는 없습니다.

Jev도 LLM처럼 트랜스포머 신경망이고, 입력도 똑같이 텍스트입니다. 차이는 출력 쪽에 있습니다.

LLM은 다음 토큰 하나를 뽑고, 그걸 입력에 붙여 또 하나를 뽑습니다. 답이 100토큰이면 신경망을 100번 돌립니다. Jev는 state와 질문을 한 번 읽고, 내가 적어 준 선택지들 위에 확률을 한꺼번에 나눠 주고 끝납니다. 신경망을 한 번 통과합니다.

그래서 응답이 대략 0.1초에서 0.5초, 가격은 입력 백만 토큰당 4.2센트, 출력은 무료입니다. 출력은 모델이 "쓴" 게 아니라 확률표를 서식에 맞춰 적은 것뿐이니까요.

대신 잃는 것도 분명합니다. 요즘 LLM이 똑똑해진 비결 중 하나는 "더 오래 생각하기"인데, Jev에는 그 단계가 없습니다. 그러니 어려운 판단 하나를 통째로 맡기면 정확도가 떨어집니다. 이건 이따 숫자로 보여드리겠습니다.

학습도 다릅니다. 챗봇은 "사람이 좋아하는 답"으로 훈련하지만, Jev는 RLCD, "확률이 현실과 맞도록" 훈련했다고 합니다. 0.8이라고 한 것들을 모아 보면 실제로 80% 정도 맞도록요. 다만 이건 모아 봤을 때의 성질이지, 0.8짜리 답 하나가 맞는다는 보장은 아닙니다.

LLM : 입력 → [신경망] → 토큰1 → [신경망] → 토큰2 → … ×100 Jev : 입력 → [신경망] → { billing: 0.84, technical: 0.16, sales: 0.00 } 끝
화면위 두 줄. LLM 줄은 길게, Jev 줄은 짧게 그려 길이 차이로 보여 준다.
주의RLCD의 보상 함수·학습 데이터는 공개되지 않았다. 물으면 "회사가 밝힌 범위는 여기까지"라고 답한다.

"그럼 정확도가 떨어지는 모델을 어떻게 믿고 쓰냐. 답은 '믿지 않는 구조로 쓴다'입니다."
4:30–6:30LEVEL 3④ 설계: 코드가 주인, Jev는 판정 한 칸
여기서 끊어도 되는 한 문장판단은 좁게 쪼개서 Jev에게 묻고, 합치고 결정하는 건 코드가 합니다. 확신이 없으면 사람에게 넘깁니다.

TypeSafe가 권하는 구조는 한 문장입니다. 평범한 소프트웨어를 만들고, AI가 꼭 필요한 칸에만 Jev를 끼워 넣어라.

흐름은 여섯 칸입니다. 원본 데이터가 있고, 코드가 필요한 것만 골라 state를 만들고, 질문과 함께 보내고, Jev가 판정하고, 답이 돌아오고, 코드가 분기합니다. 이 중 Jev가 하는 건 네 번째 칸 하나뿐입니다. 나머지 다섯 칸, 특히 무엇을 보여줄지와 답을 받아 어떻게 할지는 전부 사람이 설계하는 코드입니다.

핵심 장치가 두 개 있습니다. 첫째는 confidence입니다. 답과 함께 "확률이 한쪽에 얼마나 몰려 있나"가 옵니다. 결제 0.48, 계정 0.44처럼 갈리면 confidence가 낮게 나오고, 코드의 첫 if문이 이걸 사람에게 보냅니다. 모델이 "모르겠다"고 말할 수 있고, 코드가 그걸 존중하는 구조입니다.

둘째는 질문 쪼개기입니다. 한 실험에서 에이전트의 툴 호출을 "위험한가?" 한 질문으로 걸렀더니, 사용자가 명시적으로 요청한 정당한 작업의 39%를 막아 버렸습니다. 같은 모델에 "인젝션인가, 외부 유출인가, 되돌릴 수 없는가, 요청 범위를 넘는가"를 따로 묻고 코드가 규칙으로 합치게 하자 0%가 됐습니다. 비용은 1.7배였지만, 백만 건에 36달러 수준입니다.

if topic.confidence < 0.75 → 사람 검토 ← "모르겠다"를 먼저 잡는다 elif topic.choice == "billing" → 결제팀 (환불 요청 = refund.noul ≥ 0.7) elif topic.choice == "orders" → 배송팀 else → 계정팀
화면여섯 칸 다이어그램에서 ④만 색칠. 그다음 위 코드 네 줄.
숫자39.2% → 0% 는 typesafe-ai-firewall 실측(합성 데이터 600건, held-out 320건). "합성 데이터"라는 단서를 꼭 붙인다.
근거How to build, Confidence 페이지. 레슨 0002, 0003.
"이런 구조가 실제로 어디에 쓰이고 있는지 보겠습니다."
6:30–8:00LEVEL 4⑤ 자리: 어디에 맞고 어디에 안 맞나
여기서 끊어도 되는 한 문장Jev는 LLM을 대체하지 않습니다. LLM 옆에서, 답이 닫혀 있는 빠른 판정을 맡습니다.

잘 맞는 자리는 공통점이 있습니다. 답의 선택지가 정해져 있고, 자주 반복되고, 빨라야 합니다.

에이전트 안에서는 어떤 모델이나 툴로 보낼지 고르는 라우터, 위험한 툴 호출을 막는 게이트, LLM 답이 인용과 맞는지 보는 검증기로 씁니다. 서비스에서는 문의 분류, 콘텐츠 모더레이션, 리드 점수, 검색 결과 재정렬에 씁니다.

속도가 극단적으로 필요한 곳도 있습니다. 개발자들이 Jev로 퐁 게임을 시켰더니 결정당 평균 0.23초, 둠은 1초에 약 10번 결정하며 플레이했습니다.

안 맞는 자리도 분명합니다. 글을 써야 할 때, 왜 그렇게 판단했는지 설명이 필요할 때, 긴 문서 전체를 봐야 할 때, 계산이나 날짜 비교가 필요할 때. 이럴 땐 LLM이나 그냥 코드가 맞습니다.

8:00–9:15LEVEL 5⑥ 정직한 숫자: 광고와 실측
여기서 끊어도 되는 한 문장광고는 "193배 빠르고 444배 싸다"지만, 독립 측정은 "작은 LLM보다 2~3배 빠르고 5~7배 싸며 정확도는 비슷하다"입니다.

TypeSafe는 프론티어 LLM보다 최대 193.6배 빠르고 444.6배 싸다고 발표했습니다. 하지만 이건 회사 자체 평가이고, 비교 대상이 가장 비싼 대형 모델이었습니다.

독립 테스트에서 가장 싼 소형 모델들과 비교하면, 중간값 기준 2~3.6배 빠르고 4.7~7.5배 쌌고, 정확도는 비슷했습니다. 여전히 의미 있는 차이지만, 광고 숫자와는 다릅니다.

몇 가지 더 있습니다. 주 학습 언어가 영어라 한국어는 정답률이 약 6.5%p 낮았습니다. 대신 "한국어에서 덜 확신한다"는 것도 같이 알고 있어서, 캘리브레이션은 유지됐습니다. 그리고 논문, 모델 가중치, 학습 데이터는 아직 공개되지 않았습니다.

9:15–10:00CLOSE⑦ 맺음: 결정의 주인이 바뀐다
마지막 한 문장Jev의 진짜 변화는 속도가 아니라, AI가 하던 결정을 코드가 다시 가져온다는 점입니다.

세 가지만 기억해 주세요. 하나, Jev는 말하지 않고 결정합니다. 내가 준 선택지 중 하나와 그 확률을 돌려줍니다.

둘, 그래서 빠르고 싸지만 오래 생각하지 못합니다. 판단은 좁게 쪼개서 묻고, 확신이 없으면 사람에게 넘기는 구조로 씁니다.

셋, LLM을 대체하는 게 아니라 옆에 둡니다. LLM은 쓰고, 계획하고, 설명하고, Jev는 그 사이사이의 수많은 빠른 판정을 맡습니다. 그리고 그 판정을 어떻게 합칠지, 어디서 멈출지는 우리 코드가 정합니다. 감사합니다.

화면세 줄 요약만. 마지막 문장에서 슬라이드를 넘기지 말고 멈춘다.

예상 질문 다섯 개

"그냥 분류기(BERT) 아닌가요?"
구조상 가까운 면이 있고, 실제로 DeBERTa로 비슷한 동작을 재현한 오픈 프로젝트도 있습니다. 차이는 분류기는 학습할 때 과제가 고정되지만, Jev는 질문 문장이 실행 시점에 과제를 정한다는 점입니다. 새 분류 체계마다 다시 학습할 필요가 없습니다.
"환각이 0%라는 게 사실인가요?"
스키마 밖의 값, 예를 들어 없는 팀 이름은 절대 안 나온다는 뜻입니다. 주어진 선택지 중 틀린 걸 고를 수는 있습니다. 회사 발표에서도 그 0은 측정값이 아니라 정의상 나온 숫자라고 밝혀져 있습니다.
"왜 그렇게 판단했는지 알 수 있나요?"
없습니다. 확률 분포만 옵니다. 감사가 필요하면 질문 정의, 확률, 모델 버전을 로그로 남기고, 설명이 꼭 필요한 건은 LLM에게 넘기는 구조로 갑니다.
"한국어 서비스에 써도 되나요?"
쓸 수는 있지만 영어보다 정답률이 약 6.5%p 낮았습니다. 영어 데이터에서 정한 임계값을 그대로 쓰지 말고, 한국어 트래픽으로 다시 맞춰야 합니다.
"지금 바로 쓸 수 있나요?"
얼리 액세스 대기열이 있고, Vercel AI Gateway, Cloudflare Workers AI, OpenRouter 같은 경로로도 열려 있습니다. 가격 협상과 계약 조건은 이 자리의 범위 밖입니다.

시간이 모자랄 때

  • 5분 버전: ① 30초 → ② 1분 30초 → ③은 "한 번 통과, 그래서 빠르지만 오래 생각 못 함" 30초 → ④는 39% → 0%만 1분 → ⑦ 1분. ⑤, ⑥은 질문이 오면 답한다.
  • 청중이 비개발자: ④의 코드 판서를 빼고 "확신이 없으면 사람에게 넘긴다" 한 문장으로. 남는 시간은 ⑤의 표에 청중 업무를 놓아 보는 데 쓴다.
  • 청중이 개발자: ⑤를 1분으로 줄이고 ④에 Quick start 요청/응답 JSON을 띄운다.
